# CLAUDE.md — сервис «Отпуска»

Тестовое задание Mad Devs. Запуск локально через Docker, без облачного деплоя.

## Стек

NestJS, Prisma, PostgreSQL, React, Playwright, Jest. Почта в разработке: Mailpit (Docker Compose).

## Главные правила

1. **Источник правды по бизнес-логике: `docs/RULES.md`.** Не придумывай правила. Если ответа нет в RULES.md или он неоднозначен, остановись и задай вопрос, не делай допущений. Если код или тесты расходятся с RULES.md, сообщи об этом, не исправляй молча. RULES.md сам не правь, если только пользователь сам явно об этом не попросит: изменение правила идёт через DECISIONS.md с датой и временем, и вносит его Пользователь.
2. Перед реализацией сначала предложи короткий план (какие файлы, какие тесты, критерии приёмки и Definition of Done этапа со ссылками на пункты) и дождись подтверждения. До подтверждения код не меняй.
3. Каждое изменение поведения сопровождается тестами. Тест ссылается на пункт RULES.md (например, `// RULES §3`). Новые разделы в RULES.md добавляются в конец; если нумерация всё же изменилась, обнови ссылки в тестах.
4. Время берётся только через подменяемые часы (Clock), не через `new Date()` напрямую. Часовой пояс компании `Asia/Bishkek` задаётся переменной `COMPANY_TZ`. Даты отпусков хранятся как календарные даты без времени, моменты времени (письма, логи) в UTC. «Сегодня», начисление 1-го числа и рассылка в 09:00 считаются по поясу компании.
5. Баланс в днях с шагом 0,5, округление строго по RULES §2. Минус на экране показывается только после сдвига даты выхода (RULES §6).
6. Письма только те, что перечислены в RULES §8 (новых не добавляй; backstopper писем не получает; HR получает только письмо о новой заявке директора(он её согласует)). Календари показывают только согласованные отпуска. Заявки директора подтверждает HR, больше HR ничего не согласует.
7. Не расширяй задачу сверх issue. Заметил лишнее, запиши в конец ответа списком, не делай.

## Процесс

- Код, меняющий поведение: issue → ветка `feature/<коротко>` → PR с `Closes #N`. Ветки создаёт Пользователь; агент в нужный момент напоминает и предлагает имя ветки (с кодом этапа), сам ветки не создаёт и не переключает.
- Документы и мелочи (docs, конфиги, опечатки): коммитятся на текущей ветке вместе с кодом задачи или отдельным коммитом `docs: ... (sN)` и попадают в main через PR. Прямой коммит в main допустим, только если нет открытой ветки задачи.
- Коммиты в стиле Conventional Commits: `feat:`, `fix:`, `test:`, `docs:`, `chore:`. Код этапа ставится в конце заголовка в скобках, строчными: `feat: описание (s4)`.
- В описании PR две строки: «Агент: ...» и «Проверил/исправил я: ...». Заполняет Пользователь.
- Один PR на одну понятную задачу.
- Критерии приёмки и DoD этапа записываются в описание issue, PR ссылается на них в заголовке issue, имени ветки, коммитах (`feat: описание (s4)`, код этапа в конце заголовка), PR и записях AI-LOG и DECISIONS.
- Каждая задача и запись в логах помечается кодом этапа (S0...S10, ROADMAP, PRE) по схеме из дорожной карты: в заголовке issue, имени ветки, коммитах (`feat: описание (s4)`), PR и записях AI-LOG и DECISIONS. Агент предлагает записи уже с кодом.

## Команды

- Поднять всё: `docker compose up`
- Тесты бэкенда: `npm test`
- e2e: `npx playwright test`
- Миграции: `npx prisma migrate dev`
- Тесты времени дополнительно с `TZ=America/New_York` (ловят ошибки перехода на летнее время, которых в Бишкеке нет).

## Структура репозитория

- `docs/RULES.md`: доменные правила
- `docs/ROADMAP.md`: дорожная карта
- `architecture.md` - архитектура сервиса
- `docs/DECISIONS.md`: лог решений с временными метками
- `docs/AI-LOG.md`: ключевые промпты и что исправлено вручную

## Что делать в конце после каждой значимой задачи

- Предложи запись для `docs/AI-LOG.md` (3-5 строк: ключевой промпт, что исправил Пользователь) с датой и временем.
- Если принято решение, которого нет в RULES.md, предложи запись для `docs/DECISIONS.md` с датой и временем.
- Сверь результат с критериями приёмки и DoD из утверждённого плана: что выполнено, что нет. Невыполненное не скрывай и не переноси молча.
- Предложи обновление раздела «Состояние проекта» в README.md (статус этапа, что работает и что нет).
- В конце этапа (S0…S10) напомни Пользователю выгрузить сессию Claude Code в docs/sessions/. Перед коммитом экспорта проверь его на секреты и личные данные (пароли, токены, .env, email).

## Формат записей

- DECISIONS.md: `ГГГГ-ММ-ДД ЧЧ:ММ | решение. Причина: ... Правило: RULES §N`. Время бери командой `Get-Date` из PowerShell (Asia/Bishkek), не придумывай и не округляй.
- AI-LOG.md: дата и время, ключевой промпт, что исправил Пользователь. Ход работы («сделал #3») не пиши, он виден по истории PR.
- Записи только предлагай; в файлы их вносит и коммитит Пользователь.
