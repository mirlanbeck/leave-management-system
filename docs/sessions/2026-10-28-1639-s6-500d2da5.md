В Nest тело запроса проверяется до обработчика, поэтому код 400 всегда приходит первым, как и у отмены. Пример: James шлёт перенос с лишним полем `workDays` для отпуска, который уже «Заменена переносом». По architecture он получит 422, на деле получит 400.

`VALIDATION_FAILED → NOT_FOUND → FORBIDDEN (не владелец) → TRANSFER_SOURCE_NOT_APPROVED → TRANSFER_ALREADY_PENDING → TRANSFER_STARTED → BACKSTOPPER_REQUIRED → BACKSTOPPER_IS_SELF → BACKSTOPPER_NOT_FOUND → VACATION_DATES_ORDER → VACATION_CROSSES_YEAR → VACATION_NO_WORK_DAYS → TRANSFER_START_IN_PAST → TRANSFER_WORKDAYS_MISMATCH → VACATION_OVERLAP`.

Предлагаю для всех четырёх статусов `422 TRANSFER_SOURCE_NOT_APPROVED` («Перенести можно только одобренный отпуск»).

**В3. Issue #69 противоречит architecture §8.** Пункт issue говорит: «отменить, **перенести** и отозвать старый нельзя никому: 409 `PENDING_TRANSFER_BLOCKS`».   - `422 TRANSFER_SOURCE_NOT_APPROVED`

## В1: есть ли риски для работы приложения

Для правильных запросов риска нет: проверки те же, меняется только то, какую ошибку получит запрос, нарушающий сразу несколько правил. Разберу по случаям.
