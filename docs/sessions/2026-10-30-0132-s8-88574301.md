## Ошибки и упущения

1. **Склейка событий в одно перечитывание описана неверно.** Если запрос стартует сразу на первое событие, а события, пришедшие во время запроса, ставят пометку «перечитать ещё раз», то несколько событий подряд дают два запроса. Тест «пачка → одно перечитывание» такое не пропустит. Исправление: запуск откладывается через `setTimeout(…, 0)`, пометка остаётся для событий, которые придут во время запроса.
2. **Ручная проверка буферизации описана неточно.** Заголовок `X-Accel-Buffering: no` ставит api ([sse.controller.ts:21](apps/api/src/events/sse.controller.ts#L21)), а не nginx. Он отключает буферизацию даже при `proxy_buffering on`. Значит, чтобы тест упал, пересобрать нужно и web (`proxy_buffering on`), и api (без заголовка).
3. **Не упомянул готовность потока в e2e.** Если действие в другом контексте выполнить раньше, чем вкладка подключилась к `/events`, событие не придёт: адресаты фиксируются в момент публикации ([sse-hub.ts:89](apps/api/src/events/sse-hub.ts#L89)). Тесты будут падать через раз. Нужен признак подключения, например `data-live="connected"` на корне `Layout`. e2e ждут его перед действием.
4. **Окно при первой загрузке.** Если первая попытка подключения не удалась, событие между загрузкой данных страницы и первым успешным подключением теряется. Предлагаю такое уточнение: «первое подключение без `onChange`» относится только к случаю, когда подключились с первой попытки. Если перед успешным подключением были неудачные, `onChange` вызывается.

## Что подтвердилось и уточнилось

- **`clock.changed` и двойная перезагрузка.** Сервер фиксирует адресатов при публикации, ещё до ответа на `PUT /clock`, а доставляет асинхронно. Поэтому событие может прийти в ту же вкладку и раньше ответа, и позже. Общий `reloadOnce()` по-прежнему нужен. Новая вкладка после перезагрузки событие не получит, потому что подключилась позже публикации. Значит, `reminder.spec` с пятью установками часов подряд не зациклится.
- **Работы на страницах меньше, чем я написал.** «Загрузка…» в `CalendarPage`, `AllRequests` и `EmployeeBalances` уже показывается только до первой загрузки. При ошибке прежние данные и так остаются рядом с ErrorBox. Добавить нужно в основном вызов перечитывания по событию; формы и сообщение §6-3 лежат в отдельном состоянии и сами не сбрасываются.
- **Смена токена при открытом `Layout` невозможна.** Токен лежит в `sessionStorage`, войти можно только со страницы `/login`. При 401 и при выходе `RequireAuth` размонтирует `Layout`, и поток прерывается. Проверка «токен ещё текущий» при 401 остаётся, как в `client.ts`. Поведение при 401 совпадает с DECISIONS 2026-10-22 12:15: экран «Сессия истекла», без переподключения.
- **`cancel-recall.spec`.** Ручной `page.reload()` во время автоматической перезагрузки может упасть с `ERR_ABORTED`. Сначала дождусь, что автоматическая перезагрузка прошла (маркер `__noReload` пропал), потом проверяю.
