## Что сделано

- **Фильтр** ([event-filter.ts](apps/api/src/events/event-filter.ts)): решает, кому доставить событие. Отпуска (`vacation.*`) — тем, у кого сотрудник в календаре (`calendarScope`); смена даты выхода — сотруднику, его руководителю и HR (`canSee`); `clock.changed` — всем вошедшим. Пользователь, которого нет в структуре, ничего не получает.
- **Хаб** ([sse-hub.ts](apps/api/src/events/sse-hub.ts)):
  - события идут в одной очереди строго по одному, порядок сохраняется;
  - структура читается один раз на событие, зритель берётся из неё, а не из токена;
  - адресаты фиксируются в момент публикации: кто подключился позже события, его не получает;
  - сбой обработки пишется в лог, поток и ответ API не страдают;
  - keep-alive раз в 25 с, поток закрывается в момент `exp` токена;
  - при отключении поток и таймеры удаляются, при остановке api все потоки закрываются.
- **Контроллер** ([sse.controller.ts](apps/api/src/events/sse.controller.ts)): заголовки `text/event-stream`, `Cache-Control: no-cache`, `X-Accel-Buffering: no`. Токен проверяет глобальный guard.

- `JwtAuthGuard` теперь кладёт срок токена в запрос (`req.tokenExp`). Без этого хаб не знает, когда закрыть поток; в списке файлов плана этого не было.
