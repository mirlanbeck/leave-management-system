## Агент · 01:19

`--build` после перезагрузки не нужен, если код не менялся. Данные базы хранятся в томе `pgdata`, перезагрузка их не удалит.

1. Запустите Docker Desktop и дождитесь, пока он полностью загрузится.
2. Поднимите сервисы:

   - **Только база (и почта)**, если API и фронт запускаете локально через npm:
     ```
     docker compose up -d postgres mailpit
     ```
   - **Весь стек:**
     ```
     docker compose up -d
     ```

`-d` запускает контейнеры в фоне, чтобы терминал оставался свободным.

**Когда нужен `--build`:** только если код API или фронта изменился после последней сборки образов. Сейчас вы на ветке `feature/s8-sse-client`. Если образы `api` и `web` собирались до последних правок, запустите `docker compose up -d --build`, иначе поднимется старая версия. К базе это не относится: `postgres` и `mailpit` работают на готовых образах, им сборка не нужна.

В [docker-compose.yml](docker-compose.yml) у сервисов нет `restart:`, поэтому сами после перезагрузки они не стартуют. Команду нужно дать вручную.

Проверить, что всё поднялось: `docker compose ps`. В колонке статуса должно быть `healthy`.

## Пользователь · 01:21

значит если запущу docker compose up -d --build не ошибусь?

## Агент · 01:21

Не ошибётесь. `docker compose up -d --build` безопасна в любом случае:

- **База не пострадает.** `--build` пересобирает только `api` и `web`, у них в compose есть `build:`. `postgres` и `mailpit` работают на готовых образах, а данные лежат в томе `pgdata`, сборка их не трогает.
- **Если код не менялся**, Docker возьмёт слои из кэша, и сборка пройдёт быстро.
- **Если код менялся**, вы получите актуальную версию.

Единственный минус: команда чуть дольше, чем без `--build`. Данные же удаляет только `docker compose down -v`, флаг `-v` стирает тома. Его не используйте.

## Агент · 01:27

Да, так тоже нормально. Кнопка «Старт» в Docker Desktop делает то же, что `docker compose start`: запускает уже существующие контейнеры, база и её данные на месте.

Разница с `docker compose up -d --build` только одна: образы не пересобираются, и `api` и `web` работают на той версии кода, с которой собирались в последний раз. Если после последней сборки вы ничего не меняли в коде, всё актуально. Если меняли, выполните `docker compose up -d --build`, чтобы подтянуть свежую версию.

Проверить, что всё поднялось, можно командой `docker compose ps`: у всех четырёх сервисов статус должен быть `healthy`.
