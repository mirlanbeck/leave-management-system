## Ошибки в плане

**1. Unit-тесты с `AppModule` упадут в CI.** Prisma-клиент `src/generated/` в `.gitignore`, `postinstall` нет. Unit-job в CI делает `npm ci` и `npm test`, а `prisma generate` вызывается только в `typecheck` и `test:int`. Ни один unit-тест сейчас не импортирует Prisma. Мои `routes-closed.spec`, `problem.spec` и тест старта поднимают `AppModule`, импорт `PrismaService` падает.
- Решение: в `apps/api/package.json` сделать `"test": "prisma generate && jest ..."`, как уже сделано в `typecheck`. `DATABASE_URL` для `generate` не нужен, `typecheck` в CI это подтверждает. Это правка конфига, вынес в вопрос Q7.

**2. Зависимости должны быть в `dependencies`, не в `devDependencies`.** Runtime-образ собирается через `npm ci --omit=dev` (Dockerfile:23). Иначе API в Docker не стартует. Это касается `@nestjs/jwt`, `bcryptjs`, `class-validator`, `class-transformer`. Seed в S3-c тоже будет хешировать через `bcryptjs`.

## Неверные или неточные допущения

**3. «Сегодня» беру через `companyToday`, а не `dayOf`.** Architecture §1 называет `companyToday(now, tz)` единственным способом. В коде есть дубль: `domain/dayOf` и `clock/companyToday` делают одно и то же. Это код S3-a, в список «лишнего».

**4. Перевод `hireDate` из Prisma в строку.** Prisma отдаёт `DATE` как полночь UTC. Если перевести через `dayOf` или `companyToday` с поясом компании, при `COMPANY_TZ=America/New_York` получится предыдущий день. Готового хелпера нет (grep `getUTC` пуст).
- Решение: новая функция `fromDbDate(d: Date): CalendarDate` через `getUTC*` в `domain/calendar-date.ts`.
- Тест: unit под `test:tz`, плюс в `login.int` граница «день выхода = сегодня» при `COMPANY_TZ=America/New_York`.

**5. Тест старта без `JWT_SECRET` и проверка логов стояли не на своих местах.**
- Тест «приложение не стартует без `JWT_SECRET`» не требует БД. Переношу его из integration в unit (`startup.spec.ts`), а `jwt-config.spec` вливаю в него.
- `log-leak.spec` наоборот требует успешный вход, то есть БД. Переношу в integration (`log-leak.int.spec.ts`).
