## Агент · 05:59

Да, `docker compose up` из корня репозитория. Имя проекта `leave-management` задано в [docker-compose.yml](docker-compose.yml) через `name:`, поэтому `-p` указывать не нужно. Стек оригинала не пересекается с аудиторской копией `leave-audit-2`: у копии свои контейнеры и свой том `pgdata`.

```powershell
cd 
docker compose up --build
```

`--build` нужен, если образы api/web собирались до последних коммитов в main, иначе запустится старый код.

Обе копии используют одни и те же порты 8080, 3000, 5432, 8025 и 1025, поэтому одновременно они работать не могут. Сейчас ни один контейнер не запущен, так что порты свободны. Если потом поднимете копию аудита, сначала остановите её: `docker compose -p leave-audit-2 down`. Без `-v` её данные сохранятся.

Перед `e2e:reset` проверьте, что работает именно стек оригинала. [e2e/reset.mjs:56](e2e/reset.mjs#L56) вызывает `docker compose exec` без `-p` (находка F-7 аудита). Из этого каталога команда попадёт в `leave-management`, но если в терминале осталась переменная `COMPOSE_PROJECT_NAME=leave-audit-2`, reset сотрёт данные копии. Сбросьте её: `Remove-Item Env:COMPOSE_PROJECT_NAME`.

После запуска:
- приложение: http://localhost:8080 (логины из README, пароль `demo1234`);
- API: http://localhost:3000/health;
- почта (Mailpit): http://localhost:8025;
- полный сброс данных оригинала: `docker compose down -v`.

```powershell

```
