## 2. Проверка с типами или без

У `typescript-eslint` два варианта набора правил.

**`recommended` (без типов).** Смотрит только на текст файла: неиспользуемые переменные, `any`, `@ts-ignore` и подобное. Работает быстро, `tsconfig` не нужен.

**`recommendedTypeChecked` (с типами).** Запускает компилятор TypeScript и знает тип каждого выражения. В api используется он. Дополнительно ловит:
- `no-floating-promises`: промис, который никто не ждёт и не перехватывает;
- `no-misused-promises`: async-функция там, где ждут обычную. Например, `<form onSubmit={onSubmit}>` при `async function onSubmit` в [LoginPage.tsx](apps/web/src/pages/LoginPage.tsx) почти наверняка даст ошибку;
- `no-unsafe-*`: значения типа `any`, например результат `res.json()`.

Что это значит для задачи:
- Без типов находок меньше, и всё укладывается в объём issue (хуки).
- С типами находок больше. Обычно они чинятся без смены поведения (`void` или обёртка), но дифф растёт, а у правил `no-unsafe-*` в api уже копятся предупреждения.

**Рекомендую без типов.** Включение проверки с типами для web выпишу отдельной задачей в список «лишнего».
