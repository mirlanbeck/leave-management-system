NestJS, Node, Prisma и Postgres ставить не нужно: всё собирается и запускается внутри Docker. Версия Node задана в Dockerfile (`node:24.21.0`), Postgres и Mailpit приходят готовыми образами.

## Что установить

**Обязательно, чтобы просто запустить приложение:**

| Программа | Версия | Зачем |
|---|---|---|
| **Docker Desktop** (на Windows с движком WSL2) | Docker Engine 29.x, Compose v2+ (у вас 29.8.2 и v5.5.1) | собирает и запускает все 4 контейнера |
| **Git** | любая свежая | скачать репозиторий |

**Нужно, только если будете запускать тесты или скрипты (`npm run seed:demo`, `smoke:compose`, e2e):**

| Программа | Версия |
|---|---|
| **Node.js** | 24.x LTS, лучше 24.21.0 (в `package.json` стоит `engines: node >=24`), npm 11 идёт вместе с ним |
| Браузеры Playwright | ставятся командой, см. шаг 7 |

`seed:demo` можно запустить и без Node: `docker compose exec api node dist/seed-demo.js`.

## Шаги

1. Установите Docker Desktop, запустите его и дождитесь статуса «Engine running». Проверка:
   ```
   docker version
   docker compose version
   ```
2. Скачайте репозиторий:
   ```
   git clone https://github.com/mirlanbeck/leave-management-system.git
   cd leave-management-system
   ```
   Если нужна ветка, которая ещё не влита в main: `git checkout <ветка>`.
3. Проверьте, что свободны порты **8080, 3000, 5432, 8025, 1025**. Часто мешает локальный Postgres на 5432.
4. Запустите стек:
   ```
   docker compose up
   ```
   Первая сборка займёт несколько минут, образы весят около 1,8 ГБ. Файл `.env` создавать не нужно.
5. Откройте в браузере:
   - приложение: http://localhost:8080 (логины из README, пароль у всех `demo1234`)
   - API: http://localhost:3000/health
   - почта: http://localhost:8025
6. Демо-сценарий: выставите демо-часы на 21.10.2026 09:00, затем выполните `docker compose exec api node dist/seed-demo.js`. Подробно описано в разделе README «Демо-сценарий согласования».
7. Тесты (нужен Node 24):
   ```
   npm ci
   npm test                         # unit
   docker compose up -d postgres
   npm run test:int                 # integration
   npx playwright install chromium  # один раз, браузер для e2e
   npx playwright test              # e2e при запущенном стеке
   ```
8. Сброс к началу: `docker compose down -v`, затем `docker compose up`.

## На что обратить внимание

- Если другой компьютер на macOS или Linux: на них проект не проверялся (в README так и написано). Образы основаны на Debian, проблем ожидать не стоит, но это не проверено.
- Если у Git на той машине включена автозамена переводов строк (`core.autocrlf=true`), это может сломать shell-скрипты внутри образов. В репозитории есть `.gitattributes`, обычно он это предотвращает. Если сборка падает со странной ошибкой в скрипте, причина, скорее всего, в этом.
- Нужно не меньше ~4 ГБ RAM для Docker. На меньшем объёме сборка не проверялась.

Всё это заодно хорошая проверка раздела README «Требования к окружению» на чистой машине. Если что-то не сработает, запишите, на каком шаге, и я помогу поправить README.
