# DEVELOPMENT.md — подробности для разработки

Дополнение к [README](../README.md): то, что не нужно для запуска и проверки, но нужно, чтобы менять код и гонять тесты. Команды — из корня репозитория.

## Почта

Письма отправляет диспетчер outbox в api через SMTP в Mailpit (интерфейс http://localhost:8025). Время попыток идёт по системным часам, а не по демо-часам: при недоступном Mailpit письмо уходит после его восстановления, даже если демо-часы остановлены. Лимита попыток нет, пауза между повторами удваивается до 5 минут.

Переменные (значения по умолчанию заданы в `docker-compose.yml`, справка в `.env.example`): `SMTP_HOST`, `SMTP_PORT`, `MAIL_FROM`, `OUTBOX_POLL_MS` (интервал опроса, 2000 мс), `OUTBOX_RETRY_BASE_MS` (первая пауза, 5000 мс), `OUTBOX_RETRY_MAX_MS` (наибольшая пауза, 300000 мс).

Известное ограничение: если api упадёт после того, как SMTP принял письмо, но до пометки «отправлено», письмо уйдёт повторно (дубль).

## Проверка запуска стека

`npm run smoke:compose` поднимает стек и проверяет healthcheck, порты, /health, перезапуск api, повторный `up`, том Postgres. По ходу скрипт останавливает Postgres и перезапускает api, а в конце останавливает стек (`docker compose down`, данные в томе остаются); не запускайте его во время ручной проверки сценария. Оставить стек запущенным: `npm run smoke:compose -- --keep`.

## Миграции вне Docker

`prisma migrate dev` на хосте требует `DATABASE_URL` (по умолчанию её нет), например `npx cross-env DATABASE_URL=postgresql://leave:leave@127.0.0.1:5432/leave npx prisma migrate dev`; `cross-env` нужен, чтобы команда одинаково работала в PowerShell, cmd и bash. При старте api миграции применяются сами (`prisma migrate deploy`).

## Integration-тесты

`npm run test:int` после `docker compose up -d postgres`. Тесты идут на **отдельной БД `leave_test`** (создаётся скриптом при отсутствии, в том числе на существующем томе), рабочая БД `leave` с данными запущенного стека не затрагивается. Другая БД: переменная `TEST_DATABASE_URL`, имя БД обязано оканчиваться на `_test` (иначе скрипт и очистка тестов откажутся работать).

Выборочный запуск: сначала части путей, затем флаги jest, например `npm run test:int -- approvals vacations -t "имя теста"`; аргументы до первого флага идут в `--testPathPatterns`, флаги передаются в jest без изменений.

## e2e и `e2e:reset`

`npm run e2e` идёт на запущенном стеке (`docker compose up -d --wait`) в демо-режиме; браузер ставится один раз: `npx playwright install chromium`.

`npm run e2e:reset` стирает все данные рабочей БД `leave` (включая выставленные демо-часы), создаёт 11 пользователей, ставит часы на фиксированный момент 2026-10-21 09:00 (Бишкек) и очищает Mailpit. Его же вызывает фикстура e2e перед тестами, поэтому прогон e2e стирает данные стека. Сценарий e2e, которому нужна другая дата, ставит часы сам — тем же `PUT /clock`, что кнопка «Установить демо-время» (RULES §9-6).
