# claims.md — список проверяемых утверждений (Аудит 1, этап S2)

Составлен **до** чтения любого файла в `apps/`.
Источники истины: `docs/RULES.md` (версия от 2026-10-23), `TMP-GENERAL-REQ.pdf`.

Схема ID: `§N-k`, где `N` — номер раздела RULES, `k` — порядковый номер **пункта
верхнего уровня** в этом разделе (считая маркеры `-` первого уровня подряд).
Вложенные подпункты, таблицы и примеры относятся к родителю и получают
суффикс `.m` — это отдельные утверждения, но принадлежат пункту `§N-k`.
Пункты PDF: `PDF-T-n` (раздел «Требования», по нумерации PDF), `PDF-B-n`
(раздел «Ожидаемое поведение», нумерация по порядку маркеров `●`).

Единицы в коде (из задания аудита): дни хранятся целым числом половинок дня
(`halfDays`); календарные даты — строки `YYYY-MM-DD`.
`2,5 дня = 5 halfDays`; `15 дней = 30 halfDays`; `0,5 дня = 1 halfDay`.

## Раздел 1. Единицы, календарь, время

Пункты верхнего уровня §1: 1 — рабочие дни пн–пт / праздники; 2 — год календарный;
3 — COMPANY_TZ; 4 — даты без времени / моменты в UTC; 5 — Clock.

| ID | Утверждение |
|----|-------------|
| §1-1.1 | Отпускные дни считаются в **рабочих днях (пн–пт)**: сб и вс рабочими днями не являются. |
| §1-1.2 | Праздники **не учитываются** — списка праздников в расчёте рабочих дней быть не должно; любой пн–пт считается рабочим. |
| §1-2.1 | Год **календарный** (границы 1 января / 31 декабря), а не «год от даты выхода». |
| §1-3.1 | Часовой пояс один на всю компанию: `Asia/Bishkek` (UTC+6), задаётся `COMPANY_TZ`, **значение по умолчанию `Asia/Bishkek`**. |
| §1-3.2 | По COMPANY_TZ определяется «**сегодня**» (не по часовому поясу процесса и не по UTC). Следствие для аудита: результат доменных функций **не должен зависеть** от `TZ` процесса. |
| §1-3.3 | По COMPANY_TZ определяется момент начисления 1-го числа. |
| §1-3.4 | По COMPANY_TZ определяется 09:00 для напоминаний. |
| §1-3.5 | Индивидуальный пояс сотрудника **не поддерживается**. |
| §1-4.1 | Отпуска хранятся как **календарные даты без времени** (`YYYY-MM-DD`), моменты времени — в UTC. |
| §1-5.1 | Время берётся **только** через подменяемые часы (Clock); прямых обращений к системному времени (`new Date()` без аргументов, `Date.now()`) в домене быть не должно. |

## Раздел 2. Накопление дней

Пункты верхнего уровня §2: 1 — норма; 2 — ежемесячное начисление; 3 — первое
начисление; 4 — таблица примеров (примеры к §2-3); 5 — перенос остатка максимум 15;
6 — до даты выхода нет остатка; 7 — шаг 0,5.

| ID | Утверждение |
|----|-------------|
| §2-1.1 | Норма — **30 рабочих дней в год**, 2,5 дня в месяц. |
| §2-2.1 | Начисление происходит **1-го числа каждого месяца**. |
| §2-2.2 | Размер ежемесячного начисления — **2,5 дня (5 halfDays)**, одинаково у всех (без зависимости от стажа, роли, длины месяца). |
| §2-3.1 | Отработанные дни первого (неполного) месяца = **календарные** дни от даты выхода до конца месяца, **включая день выхода**: `worked = длина_месяца − день_выхода + 1`. Календарные, не рабочие. |
| §2-3.2 | Первое начисление = `worked / 30 × 2,5`, **но не больше 2,5 дня**. |
| §2-3.3 | Округление — **до ближайших 0,5 дня, ничья округляется вверх** (half-up; не half-even, не floor, не ceil). |
| §2-3.4 | Первое начисление приходит **1-го числа следующего месяца** (не в день выхода и не 1-го числа месяца выхода). |
| §2-3.5 | **Делитель всегда 30**, независимо от фактического числа дней в месяце (не 28/29/30/31). |
| §2-3.6 | Выход 1-го числа месяца с 31 днём: `worked=31` → `31/30×2,5 = 2,583` → упирается в максимум → **2,5**. |
| §2-3.7 | Выход 1 февраля (28 дней): `worked=28` → `28/30×2,5 = 2,333` → **2,5**. |
| §2-4.1 | Выход 1 октября 2026 → worked 31 → **2,5**. |
| §2-4.2 | Выход 5 октября 2026 → worked 27 → 2,25 (**ничья**) → **2,5**. |
| §2-4.3 | Выход 12 октября 2026 → worked 20 → 1,667 → **1,5**. |
| §2-4.4 | Выход 15 октября 2026 → worked 17 → 1,417 → **1,5**. |
| §2-4.5 | Выход 31 октября 2026 → worked 1 → 0,083 → **0**. |
| §2-4.6 | (производное от §2-3.3, тайбрейки) Ничья возникает при `worked ≡ 3 (mod 6)`: worked 3→0,5; 9→1,0; 15→1,5; 21→2,0; 27→2,5 — все округляются **вверх**. |
| §2-5.1 | Перенос остатка на следующий год — **максимум 15 дней (30 halfDays)**. |
| §2-5.2 | На 1 января порядок строго: **сначала** начисление 2,5, **потом** обрезка до 15. |
| §2-5.3 | Обрезка — ограничение сверху (`min(balance, 15)`), поэтому **отрицательный остаток не обрезается** и не поднимается до 15 или до 0. |
| §2-5.4 | Пример RULES: начало декабря 20 дней, в декабре взято 5 (→15), 1 января +2,5 → 17,5 → остаётся **15**, сгорает 2,5. |
| §2-5.5 | Срока использования перенесённых дней нет. |
| §2-6.1 | До даты выхода у сотрудника **нет остатка**: баланс до первого начисления = 0 (не отрицательный). |
| §2-6.2 | Исключение: уже полученный доступ не отзывается (§6-5, §6-7); остаток при этом считается по общему правилу журнала и может быть отрицательным. |
| §2-7.1 | Баланс измеряется в днях с шагом **0,5**: любое значение кратно 0,5, т.е. `halfDays` всегда целое; дробных halfDays быть не может. |

## Раздел 3. Заявка на отпуск (в объёме аудита: §3-4, §3-6, §3-7, §3-8, §3-9, §3-10)

Пункты верхнего уровня §3: 1 — устное согласование; 2 — состав заявки;
3 — backstopper; 4 — правила формы (дробление); 5 — один период — одна заявка;
6 — до первого начисления; 7 — даты в прошлом; 8 — комментарий; 9 — проверка
остатка; 10 — что видит сотрудник («Доступно на дату D»); 11 — статусы.

### §3-4. Правила формы заявки (дробление)

| ID | Утверждение |
|----|-------------|
| §3-4.0 | Заявка, нарушающая **любое** из трёх правил, не проходит, и система **объясняет причину** (различимый код/текст причины для каждого правила). |
| §3-4.1 | **Правило 1 (год).** Одна заявка — в пределах **одного календарного года**. Заявка через Новый год (начало в Y, окончание в Y+1) не проходит с пояснением «заявка не может охватывать два года, подайте две заявки». |
| §3-4.2 | Заявка целиком внутри одного года (в т.ч. 1 января – 31 декабря) правило 1 не нарушает. |
| §3-4.3 | **Правило 2 (минимум 1 рабочий день).** Заявка без единого рабочего дня (например, только сб+вс) не проходит. |
| §3-4.4 | Заявка, содержащая хотя бы один пн–пт, правило 2 проходит. |
| §3-4.5 | **Правило 3 (пересечение).** Нет пересечения с другой **активной** заявкой или отпуском того же сотрудника; активные — «На согласовании» и «Одобрена». Текст: «у вас уже есть заявка на эти даты: с … по …». |
| §3-4.6 | Заявки в статусах «Отклонена», «Отменена», «Заменена переносом» пересечение **не** образуют. |
| §3-4.7 | Пересечение — любое наложение интервалов включительно: смежные периоды (окончание = начало − 1 день) пересечением не являются, совпадение одной даты — является. |

### §3-6. До первого начисления

| ID | Утверждение |
|----|-------------|
| §3-6.1 | Заявку **нельзя подать до первого начисления**, пояснение «у вас ещё нет накопленных дней». |
| §3-6.2 | Граница: дата первого начисления = 1-е число месяца, следующего за месяцем даты выхода (§2-3.4). Пока «сегодня» < этой даты — отказ; начиная с неё — проходит. Проверка привязана к «сегодня» (момент подачи), а не к дате начала отпуска. |
| §3-6.3 | Пример RULES (§7, Сотрудник 3): дата выхода 2026-10-12, первое начисление 1,5 дня, **до 1 ноября 2026 заявку подать нельзя** (1 ноября — можно). |
| §3-6.4 | Если первое начисление = 0 дней (выход 31-го числа, §2-4.5), запрет снимается всё равно с 1-го числа следующего месяца — это проверка **даты**, а не величины остатка (нехватку ловит §3-9). См. неоднозначность A-2. |

### §3-7. Даты в прошлом

| ID | Утверждение |
|----|-------------|
| §3-7.1 | Заявка «в прошлом», если **дата начала раньше сегодняшней** (по Clock и COMPANY_TZ). |
| §3-7.2 | Начало **сегодня** «в прошлом» **не считается** (строгое сравнение). |
| §3-7.3 | Начало **завтра** и позже — не «в прошлом». |
| §3-7.4 | Для заявки «в прошлом» дата начала должна быть **в пределах текущего календарного года**. |
| §3-7.5 | Заявка с началом в **прошлом году** отклоняется с пояснением (отдельная причина, не совпадающая с §3-4.1). |
| §3-7.6 | Для заявки «в прошлом» **комментарий обязателен**; без комментария — не проходит. |
| §3-7.7 | Остальные проверки для «в прошлом» те же (год, ≥1 рабочий день, пересечение, остаток). |

### §3-8. Комментарий

| ID | Утверждение |
|----|-------------|
| §3-8.1 | Комментарий к обычной (не «в прошлом») заявке **необязателен**: пустой/отсутствующий комментарий не является причиной отказа. |
| §3-8.2 | Обязателен **только** для дат в прошлом (§3-7.6). |

### §3-9. Проверка остатка

| ID | Утверждение |
|----|-------------|
| §3-9.1 | Рабочие дни заявки **не больше накопленного к дате начала отпуска** — по формуле «Доступно на дату D» при D = дата начала (§3-10). |
| §3-9.2 | Сравнение нестрогое: заявка ровно на весь доступный остаток проходит. |
| §3-9.3 | Дни заявок «На согласовании» **не резервируются** (не уменьшают доступное). |
| §3-9.4 | Если дней не хватает — заявка не проходит, система объясняет причину. |

### §3-10. «Доступно на дату D»

| ID | Утверждение |
|----|-------------|
| §3-10.1 | `Доступно(D) = баланс сегодня + начисления и обрезки до 15 на даты **строго после сегодня и до D включительно**`. |
| §3-10.2 | «Баланс сегодня» — за вычетом **всех** списаний журнала (§6-6), включая списания с датами в будущем. |
| §3-10.3 | События **сегодняшнего дня** уже входят в баланс сегодня и повторно **не** считаются (нет двойного счёта, в т.ч. когда сегодня = 1-е число). |
| §3-10.4 | События **самой даты D** учитываются (граница включительно), в порядке §6: начисление, затем обрезка. |
| §3-10.5 | Для **D в прошлом** берётся баланс сегодня (без отката событий назад). |
| §3-10.6 | Для **D = сегодня** берётся баланс сегодня. |
| §3-10.7 | В прогноз входят **и начисления, и обрезки** до 15 на каждое 1 января интервала (обрезка не теряется). |
| §3-10.8 | По этой формуле проверяется заявка при подаче и при согласовании; для переноса остаток не проверяется (§5). |

## Раздел 5. Перенос и отмена (в объёме аудита: дни возврата — §5-6, §5-11, плюс §5-4)

Пункты верхнего уровня §5: 1 — перенос только до начала; 2 — что такое перенос;
3 — отмена заявки-переноса; 4 — отмена до начала; 5 — отзыв из отпуска (HR);
6 — **дни возврата при отзыве**; 7 — сотрудник после начала не отменяет;
8 — изменение дат = перенос; 9 — «отпуск начался» = сегодня ≥ даты начала;
10 — «На согласовании» после начала не отменяет никто; 11 — **допустимый диапазон
даты выхода при отзыве**; 12 — цепочка переносов.

| ID | Утверждение |
|----|-------------|
| §5-4.1 | Отмена **до начала** отпуска возвращает дни **полностью** (все рабочие дни заявки). |
| §5-6.1 | **День выхода считается рабочим, то есть неиспользованным** — он входит в возврат. |
| §5-6.2 | Возвращаются **рабочие дни** (пн–пт) с даты выхода **до конца отпуска включительно**. |
| §5-6.3 | Пример RULES: отпуск 19–30 октября 2026, выход 27 октября → возвращаются 27, 28, 29, 30 → **4 дня**. |
| §5-6.4 | Выход на **дату начала** возвращает **все** рабочие дни отпуска (эквивалент полной отмены). |
| §5-6.5 | Выход на **дату окончания**: возврат = 1 день, если дата окончания пн–пт, и **0 дней**, если сб/вс. |
| §5-6.6 | Выход на **выходной** внутри отпуска: возвращаются рабочие дни от этой даты до конца (сам выходной не в счёт). |
| §5-11.1 | Дата выхода при отзыве допустима **от даты начала до даты окончания включительно**. |
| §5-11.2 | Дата **после окончания** отзывом не является и **отклоняется с пояснением**. |
| §5-11.3 | Дата **раньше даты начала** недопустима. |
| §5-11.4 | Относительно «сегодня» ограничений нет: допустима дата в прошлом и в будущем, лишь бы внутри отпуска. |
| §5-11.5 | Сумма возвратов по одному списанию не превышает списанного (§6-8.2). |

## Раздел 6. Баланс по журналу (в объёме аудита: §6-6, плюс §6-1, §6-4, §6-8)

Пункты верхнего уровня §6: 1 — меняет только HR, накопление пересчитывается всегда;
2 — предупреждение; 3 — разовое сообщение; 4 — отрицательный остаток; 5 — доступ не
отзывается; 6 — **баланс по журналу**; 7 — признак «доступ получен»; 8 — возврат и
цепочка переносов.

| ID | Утверждение |
|----|-------------|
| §6-1.1 | При смене даты выхода **накопление пересчитывается всегда** (в любую сторону). |
| §6-4.1 | После сдвига даты выхода на более позднюю остаток **может стать отрицательным** и таким остаётся (не обрезается до 0). |
| §6-6.1 | Баланс вычисляется **по журналу событий**, отдельно не хранится. |
| §6-6.2 | «Баланс сегодня» учитывает все **начисления** с датой **до сегодняшней включительно**. |
| §6-6.3 | «Баланс сегодня» учитывает все **обрезки 1 января** с датой до сегодняшней включительно. |
| §6-6.4 | «Баланс сегодня» учитывает **все списания и возвраты независимо от их даты**, включая будущие. |
| §6-6.5 | `approvedAt` и дата отмены используются **только как порядок событий** при расчёте обрезки. |
| §6-6.6 | Списание/возврат попадает «до обрезки 1 января Y», если его дата **по COMPANY_TZ строго раньше** 1 января Y. Граница (UTC+6): `31.12 17:59Z` (= 23:59 Бишкек 31.12) → **до** обрезки; `31.12 18:00Z` (= 00:00 Бишкек 01.01) → **не** строго раньше → **после** обрезки. |
| §6-6.7 | События одного дня применяются в порядке: **начисление → обрезка → действия пользователей**. |
| §6-6.8 | `approvedAt` и дата отмены фиксируются по Clock в момент действия и **не пересчитываются**. |
| §6-6.9 | При смене даты выхода пересчитываются **начисления и обрезки**; **списания и возвраты остаются на своих датах**. |
| §6-6.10 | Списание создаётся при **окончательном согласовании** заявки и остаётся за этой заявкой при любых дальнейших изменениях её статуса. |
| §6-6.11 | При утверждении переноса списание остаётся за старой заявкой; у заявки-переноса **своего списания нет**; баланс не меняется. |
| §6-6.12 | **Возврат создаётся только отменой или отзывом** и привязан к заявке, по которой было списание. |
| §6-8.1 | Возврат всегда привязывается к списанию **корня цепочки** переносов, даже если отменяется/отзывается более позднее звено. |
| §6-8.2 | Сумма возвратов по одному списанию **не превышает списанного**. |
| §6-8.3 | Повторная отмена того же отпуска второго возврата не создаёт («уже обработана»). |

## Раздел 8. Дата напоминания (в объёме аудита: §8-3)

Пункты верхнего уровня §8: 1 — канал; 2 — письма о заявке/решении;
3 — **напоминание за N рабочих дней**; 4 — дата начала уже наступила;
5 — получатели; 6 — HR не получает напоминание; 7 — HR не получает письма об
отменах/переносах; 8 — отмена/отзыв писем не порождают.

| ID | Утверждение |
|----|-------------|
| §8-3.1 | Напоминание — за **N рабочих дней** до начала, `N` из `REMINDER_DAYS`, **по умолчанию 3**. |
| §8-3.2 | Время отправки — **09:00 по COMPANY_TZ**. |
| §8-3.3 | **Дата напоминания = N-й рабочий день, предшествующий дате начала**; считаем назад от даты начала, **сама дата начала не считается**; выходные пропускаются и N не уменьшают. |
| §8-3.4 | Пример RULES, N=3: начало вторник 10 ноября 2026 → пн 9 (1), пт 6 (2), чт 5 (3) → **четверг 5 ноября 2026**. |
| §8-3.5 | Пример RULES, N=3, начало **суббота** 14 ноября 2026 → пт 13 (1), чт 12 (2), ср 11 (3) → **среда 11 ноября 2026**. |

## Предварительные неоднозначности (зафиксированы до чтения кода)

- **A-1.** §2-3.2 «не больше 2,5» при округлении half-up до 0,5 **ненаблюдаемо** на
  выходе: `worked=31 → 31/6 = 5,167 halfDays → round half-up → 5 = 2,5` и без
  ограничения. Ограничение проявилось бы только при ином округлении (ceil).
  Отличить «cap есть» от «cap нет» по результату нельзя — нужна проверка по коду.
- **A-2.** §3-6: «до первого начисления» — это проверка **даты** первого начисления
  или **величины** накопленного? При выходе 31-го числа первое начисление = 0 дней
  (§2-4.5), и с 1-го числа запрет снимается, хотя накопленных дней по-прежнему нет.
  Формулировка «у вас ещё нет накопленных дней» намекает на величину.
- **A-3.** §2-2 vs §2-3.4: получает ли сотрудник на 1-е число месяца, следующего за
  месяцем выхода, **только** частичное первое начисление, или частичное **плюс**
  обычные 2,5? Естественное чтение — только частичное, но прямо не сказано.
- **A-4.** §3-4.1 (один год) vs §3-7.5 (начало в прошлом году): заявка 20.12.(Y−1) –
  10.01.Y нарушает оба правила. Какая причина возвращается — не задано.
- **A-5.** §3-4.0: возвращается **первая** найденная причина или **все**? Порядок
  проверок формы в RULES не зафиксирован вообще.
- **A-6.** §5-6.5: выход на дату окончания, если она сб/вс, даёт возврат 0 дней.
  RULES этот случай прямо не разбирает (пример §5-6.3 — рабочий день), но из
  «возвращаются рабочие дни с даты выхода до конца отпуска» следует 0.
- **A-7.** §3-10.1 говорит «начисления и обрезки до 15 дней на каждое 1 января» —
  буквально это сужает прогноз до январских событий и исключает обычные месячные
  начисления 1-го числа и первое начисление. Системное чтение (§2-2) требует
  учитывать все начисления. Буквальное и системное чтение расходятся.
- **A-8.** §6-6.7 задаёт порядок «начисление, обрезка, действия пользователей», но
  не порядок **внутри** группы действий одного дня; для суммы это неважно, но важно
  для §6-8.2 («сумма возвратов не превышает списанного»).
