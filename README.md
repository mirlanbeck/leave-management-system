# leave-management-system

Full-stack employee leave management system with leave balance tracking, approval workflows, team calendars and HR administration

## Как сделан проект

- **Инструмент:** Claude Code (расширение для VS Code).
- **Модель:** Claude Sonnet 5.5; также Claude Opus 5.5 (уровень рассуждений medium).
- **Почему:** Claude Code работает прямо в репозитории: читает код, правит файлы, запускает команды и тесты, а каждая сессия сохраняется в виде JSONL-лога с временными метками. Sonnet 5.5 выбран как баланс качества и расхода лимитов тарифа Pro.
- **Вне Claude Code:** отдельные вопросы (разбор требований, расход лимитов, формулировки для документации) обсуждались в чате claude.ai. Код проекта этим чатом не писался.
- **Лог работы:** `docs/DECISIONS.md` (решения с датой и временем), `docs/AI-LOG.md` (ключевые промпты и что исправлено вручную), история коммитов, экспорт сессий Claude Code в `docs/sessions/`.

## Требования к окружению

**Порты (только 127.0.0.1):** web 8080, api 3000, Postgres 5432, Mailpit 8025 (интерфейс) и 1025 (SMTP). Порты должны быть свободны.

**Запуск:** `docker compose up` из корня репозитория (`cp .env.example .env` не нужен, демо-значения заданы в `docker-compose.yml`). Страница: http://localhost:8080, проверка API: http://localhost:3000/health, почта: http://localhost:8025. Данные Postgres лежат в именованном томе `pgdata`; полный сброс: `docker compose down -v`.

**Почта:** письма отправляет диспетчер outbox в api через SMTP в Mailpit (интерфейс http://localhost:8025). Время попыток идёт по системным часам, а не по демо-часам: при недоступном Mailpit письмо уходит после его восстановления, даже если демо-часы остановлены. Лимита попыток нет, пауза между повторами удваивается до 5 минут. Переменные (значения по умолчанию заданы в `docker-compose.yml`, справка в `.env.example`): `SMTP_HOST`, `SMTP_PORT`, `MAIL_FROM`, `OUTBOX_POLL_MS` (интервал опроса, 2000 мс), `OUTBOX_RETRY_BASE_MS` (первая пауза, 5000 мс), `OUTBOX_RETRY_MAX_MS` (наибольшая пауза, 300000 мс). Известное ограничение: если api упадёт после того, как SMTP принял письмо, но до пометки «отправлено», письмо уйдёт повторно (дубль).

**Проверка запуска:** `npm run smoke:compose` (поднимает стек, проверяет healthcheck, порты, /health, перезапуск api, повторный `up`, том Postgres).

**Integration-тесты вне Docker:** сначала поднимите Postgres: `docker compose up -d postgres`. Затем `npm run test:int`. Тесты идут на **отдельной БД `leave_test`** (создаётся скриптом при отсутствии, в том числе на существующем томе), рабочая БД `leave` с данными запущенного стека не затрагивается. Другая БД: переменная `TEST_DATABASE_URL`, имя БД обязано оканчиваться на `_test` (иначе скрипт и очистка тестов откажутся работать). Выборочный запуск: сначала части путей, затем флаги jest, например `npm run test:int -- approvals vacations -t "имя теста"`; аргументы до первого флага идут в `--testPathPatterns`, флаги передаются в jest без изменений. Unit-тесты (`npm test`) БД не требуют.

**Миграции вне Docker:** `prisma migrate dev` на хосте требует `DATABASE_URL` (по умолчанию её нет), например `npx cross-env DATABASE_URL=postgresql://leave:leave@127.0.0.1:5432/leave npx prisma migrate dev`; `cross-env` нужен, чтобы команда одинаково работала в PowerShell, cmd и bash.

**`e2e:reset`:** стирает все данные рабочей БД `leave` (включая выставленные демо-часы), создаёт 11 пользователей, ставит часы на фиксированный момент 2026-10-21 09:00 (Бишкек) и очищает Mailpit. Не запускайте его на стеке, в котором вручную проверяете сценарий. Сценарий e2e, которому нужна другая дата, ставит часы сам.

## Демо-сценарий согласования (seed:demo)

Демо-часы остановлены и меняются только полосой часов в шапке (RULES §9). Даты демо-заявок считаются от текущего значения часов: первая начинается с первого понедельника не раньше «сегодня + 14 дней». Поэтому часы выставляются **до** `seed:demo` (RULES §9-6).

1. `docker compose up` (демо-режим `DEMO_MODE` в compose уже включён).
2. Откройте http://localhost:8080 и войдите любым демо-пользователем, например `james`.
3. В полосе демо-часов укажите дату **21.10.2026** и время **09:00** и нажмите «Установить».
4. Выполните `npm run seed:demo` (или `docker compose exec api node dist/seed-demo.js`). Повторный запуск ничего не дублирует.
5. Что увидеть на странице «Согласование» (даты при часах 21.10.2026):
   - `daniel`: заявка Sophie Bennett 11.11–17.11 с предупреждением о пересечении с одобренным отпуском James Walker 09.11–13.11;
   - `olivia`: заявка Grace Morgan 16.11–20.11 без предупреждения;
   - `emily` (HR): в «Мои заявки» своя заявка 16.11–20.11 «На согласовании», в «Допуск HR» заявка директора Margaret Collins 09.11–13.11;
   - `thomas`: заявка Emily Carter 16.11–20.11;
   - Mailpit (http://localhost:8025): 10 писем — 7 о новых заявках и 3 о решениях.
6. Что увидеть на странице «Календарь» (часы в октябре, поэтому нажмите «Следующий месяц →»; в календаре только одобренные отпуска):
   - `james`: свой отпуск 09.11–13.11;
   - `daniel`: отпуск James Walker 09.11–13.11 и «Остатки команды» (James, Liam, Sophie);
   - `olivia`: отпуск Henry Price 23.11–27.11 (заявка Grace «На согласовании» и отклонённая заявка Chloe не видны);
   - `emily` (HR): вся компания — James Walker и Henry Price.

**Как переключать дату.** Полосой демо-часов, в любую сторону, любым вошедшим пользователем; после «Установить» страница перезагружается. Откат часов назад не отменяет уже состоявшиеся события (списания, письма), а прогноз «Доступно на дату» может разойтись с фактическим балансом — известное ограничение демо-режима (RULES §9-5).

**Вернуться к началу:** `docker compose down -v`, затем `docker compose up`: БД, часы и письма создаются заново. `npm run e2e:reset` тоже стирает данные и ставит часы, но он для автотестов: не запускайте его на стеке, где проверяете сценарий вручную.

Сетка месяца (выходные затенены) и список отпусков с полными датами, переход между месяцами, месяц в адресе (`?month=2026-11`) сохраняется при перезагрузке. Эпик S5 закрыт (#53; PR #48, #50, #52, #55, #57, #59, #61, #63 и #65).

S6-a (#67, эпик #66): отмена и отзыв. `POST /vacations/{id}/cancel`: владелец отменяет до начала (в том числе HR свой отпуск); одобренный отпуск — полный возврат дней, заявка «На согласовании» — без возврата; после начала сотрудник отменить не может, «На согласовании» после начала не отменяет никто. `POST /vacations/{id}/recall`: HR отзывает из идущего отпуска (начало ≤ сегодня ≤ окончание, в том числе себя) с датой выхода от начала до окончания; возвращаются рабочие дни с даты выхода. Возврат всегда к списанию корня цепочки, датируется по Clock, один на заявку (повтор и параллельные запросы — «уже обработана»). Писем нет; после отмены и отзыва отпуск пропадает из календаря. Страница «Отпуск»: «Отменить» в «Моих заявках» с подтверждением, остаток перечитывается. Экран HR (`/hr`): «Все заявки» компании со статусами и пометками, кнопка «Отзыв» с датой выхода только над идущим одобренным отпуском.
